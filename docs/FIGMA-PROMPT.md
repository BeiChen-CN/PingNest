# PingNest Figma Make 提示词手册

> 适用对象：Figma Make / Figma AI 设计助手  
> 目标：为当前 Electron + React 项目生成完整、可开发落地的 Windows 桌面应用 UI，而不是概念稿或营销页面。  
> 推荐用法：按顺序逐段提交，不要一次性粘贴全部提示词。

---

## 1. 使用方法

1. 新建一个空白 Figma Make 项目。
2. 首先提交「提示词 00」和「提示词 01」，建立稳定的产品上下文。
3. 依次提交设计系统、应用框架和五个业务页面提示词。
4. 页面完成后再提交状态、响应式、原型和最终审查提示词。
5. 如果 Figma Make 偏离约束，使用文末的「定向修正提示词」，不要要求它推倒重做。

每次继续生成页面时，建议在提示词最前面附加：

```text
继续沿用当前 PingNest 文件中的设计系统、Variables、组件和命名，不创建第二套视觉语言，不重置已有页面。只修改本次指定的页面或组件。
```

## 2. 当前项目事实

以下内容是当前项目已经支持的真实能力。设计稿必须以此为准，不要自行扩展产品范围。

- 产品名称：`PingNest`，中文名「微信通知伴侣」。
- 平台：Windows 桌面端，Electron + React。
- 数据来源：本地微信 WCDB 数据库监控。
- 数据原则：所有配置和通知历史仅保存在本机。
- 主窗口默认尺寸：`1180 × 760`。
- 主窗口最小尺寸：`960 × 640`。
- 主导航：概览、历史、静音、外观、设置。
- 桌面通知支持：位置、停留时间、透明度、摘要显示、同会话聚合、点击行为。
- 点击通知仅支持「打开通知历史」或「无操作」。
- 静音规则支持：名称、关键词、会话 ID、任一/全部匹配、启用状态。
- 历史筛选支持：搜索、全部/今天、全部/私聊/群聊。
- 系统设置支持：开机启动、关闭到托盘、托盘提示、自动重连、重连间隔、历史保留和自动清理。
- 在线更新尚未接入，不要设计可点击的「检查更新」功能。
- 当前版本以浅色界面为主，不要额外生成暗色模式。

不要虚构以下能力：

- 不要设计聊天窗口、消息输入框、聊天气泡或联系人管理。
- 不要设计直接回复消息、发送消息、表情面板或语音输入。
- 不要设计云同步、账号登录、跨设备同步或团队协作。
- 不要设计复杂统计报表、虚假健康评分或无来源的趋势图。
- 不要设计打开微信并精准跳转会话的选项。
- 不要设计导出 JSON、自动更新或多显示器管理，除非后续明确要求。

## 3. 提示词 00：上下文锁定

将这一段作为第一次输入，用于防止 Figma Make 把项目做成官网或聊天软件。

```text
你是一名资深 Windows 桌面应用产品设计师和 Design System 设计师。

接下来请持续为 PingNest 设计一套完整的高保真 UI。它是运行在 Windows 上的本地通知管理工具，用于监听微信消息、显示桌面弹窗、查询通知历史、配置静音规则和系统参数。

它不是聊天软件，也不是官网、落地页、移动社交应用或数据分析 SaaS。第一屏必须直接是可操作的桌面应用，不要生成 Hero、营销文案、价格方案、用户评价或产品功能介绍。

设计优先级：
1. 信息可快速扫描。
2. 常用操作路径短。
3. 状态和错误反馈明确。
4. 界面安静、专业、克制。
5. 所有布局可以直接映射到 Electron + React 实现。

整个设计过程必须复用同一套 Variables、Auto Layout、组件和 Variants。不要在后续页面创建风格不同的新组件。
```

## 4. 提示词 01：全局产品与视觉方向

```text
为 PingNest 建立完整的产品视觉方向。

产品气质：
- 安静、专业、可靠、本地优先。
- 高信息密度但不拥挤，接近成熟的 Windows 生产力工具。
- 使用中性浅灰和白色作为主体，绿色仅用于运行状态、当前选中项、开关和主操作。
- 通过对齐、间距、字体权重和细边框建立层级，不依赖大量阴影或彩色卡片。

明确禁止：
- 不使用渐变、玻璃拟态、Mica 大面积透明、霓虹灯或发光边框。
- 不使用装饰性插画、3D 图形、渐变球、背景光斑和 Emoji 图标。
- 不使用巨大标题、Hero 构图或营销页面布局。
- 不使用卡片嵌套卡片。
- 不让页面被同一绿色色系统治。
- 不使用超过 8px 的卡片圆角。
- Hover 不允许缩放或导致布局移动。

界面应优先表现为一个真实可用的工具，而不是漂亮但无法操作的概念稿。
```

## 7. 提示词 04：概览页

```text
设计 PingNest 的“概览”页面，主 Frame 为 1180 × 760，使用已有主窗口框架。

页面标题：通知伴侣 - 运行概览
副标题：监控本地微信聊天事件并在桌面显示通知

标题右侧：
- 服务状态：运行中/未连接，使用状态点加文字，不能只用颜色。
- 桌面通知总开关。

第一行摘要区：
- 三个等宽、紧凑的状态区块，不使用大号 KPI 卡片。
- 监听状态：正在监控进程；辅助信息 WeChat.exe 已检测。
- 今日通知：4 次；辅助信息 已保存 4 条本地记录。
- 静音规则：0 条已启用；辅助信息 符合规则的消息仅进入历史。
- 数值或核心状态使用 15–16px / 600，不使用 32px 以上大数字。

第二行采用主次两列：
- 左侧为“最近捕获的微信通知”，占剩余宽度。
- 右侧为“监控运行状态”，固定约 250px。

最近通知列表：
- 标题栏左侧为区块标题，右侧为“查看全部”文本操作。
- 最多展示 5 条。
- 每行包含 32px 头像、会话名称、一行消息摘要、时间、未读状态。
- 使用真实中文示例，不使用 Lorem Ipsum。
- Hover 使用浅绿色；点击后进入历史并选中对应记录。

监控运行状态：
- 数据库连接：正常/未就绪。
- 连接账号：微信 ID 或未配置。
- 自动重连：已开启/已关闭。
- 记录估算大小：1 KB。
- 展示真实的“今日记录占全部记录比例”，不要生成虚假健康评分。
- 底部提供“立即检查”次级按钮。

其他状态：
- 配置不完整时显示一条横向连接引导，包含数据库图标、简短说明和“一键配置”。
- 自动配置进行中时按钮显示 Loading，下面显示步骤日志。
- 页面底部显示“所有通知仅保存在本地，不上传任何服务器”。

同时输出以下 Variants：
- 正常运行。
- 微信未运行。
- 数据库未连接。
- 自动配置进行中。
- 没有最近通知。
```

## 8. 提示词 05：通知历史页

```text
设计 PingNest 的“通知历史”页面，保持高信息密度和快速扫描能力。

页面标题：通知历史
副标题：搜索、筛选并处理本机保存的通知记录

工具栏：

- 时间筛选只包含：时间：全部、时间：今天。
- 类型筛选只包含：类型：全部、私聊、群聊。
- 显示当前结果数量，例如“4 条”。
- 右侧提供“清空全部”危险次级按钮。

- 右侧详情面板固定约 252px。

- 高度约 48–52px。
- 包含 28px 头像、会话名、单行摘要、私聊/群聊标签、时间。
- 未读记录使用文字语义和小圆点，不只依赖颜色。
- Hover 使用浅绿色。
- Selected 使用浅绿色背景和左侧 3px 绿色指示线。
- 长联系人、长消息和时间不能互相覆盖，使用稳定 Grid 和省略号。

确认对话框：
- 标题：清空全部通知记录？
- 正文必须显示即将删除的记录数量。
- 默认焦点放在“取消”。
- 危险按钮为“清空记录”。
- 支持 Escape 关闭、Tab 焦点限制和关闭后的焦点恢复。

输出以下页面状态：
- 有数据、第一条未读并被选中。
- 搜索有结果。
- 搜索无结果。
- 历史完全为空。
- 删除确认对话框打开。
- 操作失败的内联错误提示。
```

## 9. 提示词 06：静音规则页

```text
设计 PingNest 的“静音与屏蔽规则管理”页面。

页面标题：静音与屏蔽规则管理
副标题：符合规则的微信消息将不触发桌面弹窗

页面结构：
- 右上方提供“新增规则”主按钮，使用 Plus 图标。

- 关键词/规则名称。
- 匹配方式：包含任一或精确组合。
- 启用状态：Toggle Switch。
- 命中次数。
- 范围：全部或 N 个会话。
- 编辑图标按钮。

规则编辑表单：
- 标题：新增过滤规则或编辑过滤规则。

- 匹配方式只包含“任一条件命中”和“全部条件满足”。
- 提供“立即启用此规则”开关。
- 底部固定“保存”和“取消”。
- 规则名称为空，或关键词和会话 ID 均为空时，保存按钮禁用。
- 打开编辑器后优先聚焦规则名称。
- 表单错误显示在对应字段下方，不只显示页面顶部错误。

空状态：
- 使用 VolumeX 线性图标。
- 标题：暂无静音规则。
- 说明：新增规则后，命中的消息仍会保存在通知历史中。
- 提供新增规则操作。

输出以下状态：
- 空规则列表。
- 多条启用/停用规则。
- 新增编辑器打开。
- 编辑已有规则。
- 保存按钮禁用。
- 保存失败字段错误。
```

## 10. 提示词 07：通知外观与桌面弹窗

```text
设计 PingNest 的“外观与弹窗偏好设置”页面，以及独立桌面通知组件。

页面标题：外观与弹窗偏好设置
副标题：自定义桌面通知的位置、停留时间和交互逻辑

桌面布局：
- 左侧为设置区，宽度约 40%。
- 右侧为实时预览区，宽度约 60%。
- 两个区域并列但不嵌套卡片。

设置区：
- 弹窗显示位置：使用一个稳定尺寸的屏幕位置选择器。
- 支持顶部居中、左上、右上、左下、右下。
- 每个位置按钮有 aria-pressed 对应的视觉选中状态。
- 显示当前中文位置，例如“当前：屏幕右下角”。
- 显示持续时间：3–15 秒自定义 Slider，右侧显示当前秒数。
- 悬浮窗透明度：70%–100% Slider，右侧显示百分比。
- 多消息聚合显示：Toggle Switch。
- 显示消息摘要：Toggle Switch。
- 弹窗点击行为：打开通知历史、无操作。

Slider 要求：
- 自定义浅灰 Track、绿色已完成部分和清晰 Thumb。
- 不能使用浏览器默认黑色滑杆。
- Focus、Hover、Disabled 状态明确。

实时预览区：
- 使用中性浅灰工作区作为预览背景。
- 通知在右上方显示，但四周保留至少 24px 空间。
- 标题和说明位于预览区边缘，不要覆盖通知。
- 预览随设置变化，但自身尺寸保持稳定。

桌面通知组件：
- 宽度约 400px，最小高度约 104px，圆角 8px。
- 白色高不透明背景、1px 边框、轻阴影。
- 顶部 3px 强调色线。
- 包含 40px 头像、联系人、时间、最多两行摘要和关闭按钮。
- 关闭按钮默认可见但低强调，Hover/Focus 时增强。
- 同会话合并时显示数字徽标。
- 撤回消息使用 Undo 图标和琥珀色顶部线。
- “打开通知历史”状态中，正文区域是明确可点击的原生按钮。
- “无操作”状态中，正文区域使用默认光标且不可聚焦；关闭按钮仍可操作。
- 不要模仿 Windows 原生 Toast，也不要制作聊天气泡。

输出组件状态：
- 普通可点击通知。
- 无操作通知。
- 同会话合并 3 条。
- 消息撤回。
- 隐藏摘要。
- 70% 和 100% 透明度示例。
- Enter/Space 焦点状态。
```

## 12. 提示词 09：Loading、Empty、Error 与反馈状态

```text
为 PingNest 建立完整的状态设计页，不新增业务功能。

必须包含：

一、应用级状态

- Electron Preload 未加载：显示“应用初始化失败”、原因、重试按钮。
- 本地状态读取失败：顶部 Inline Alert，带 AlertTriangle 图标和关闭按钮。
- 配置保存失败：保留原值并显示可恢复错误提示。

- 微信未运行。
- WCDB 未就绪。
- 正常监听。
- 自动配置进行中。
- 自动配置失败，保留步骤日志和下一步操作。

三、历史状态
- 完全无通知。
- 搜索无结果。
- 复制成功。
- 删除失败。
- 清空确认。

四、规则状态
- 无规则。
- 表单未完成。
- 字段错误。
- 保存进行中和保存失败。

- Error 使用图标、标题、正文和恢复操作，不能只显示红色边框。

- 所有错误提示应具备 aria-live 或 role=alert 对应的视觉说明。
```

## 14. 提示词 11：Prototype 交互流程

```text
为已经完成的 PingNest 页面建立可演示的 Interactive Prototype。

主流程一：查看通知
1. 从概览点击一条最近通知。
2. 跳转到历史页。
3. 自动选中对应通知。
4. 未读角标减少。
5. 详情面板显示对应内容。

主流程二：搜索和清空历史
1. 在历史搜索框输入关键词。
2. 列表过滤并更新结果数量。
3. 点击清空全部。
4. 打开危险确认对话框，默认聚焦取消。
5. 取消后返回触发按钮；确认后显示空状态。

主流程三：新增静音规则
1. 点击新增规则。
2. 右侧编辑器打开并聚焦规则名称。
3. 未填写必要条件时保存禁用。
4. 填写规则名称和关键词后保存启用。
5. 编辑器关闭，表格出现新规则。

主流程四：调整通知外观
1. 修改位置、停留时间、透明度和摘要开关。
2. 右侧预览即时变化。
3. 将点击行为改为无操作。
4. 通知正文失去可点击和焦点状态，关闭按钮保持可用。

主流程五：设置失败恢复
1. 用户切换一个系统设置。
2. 展示短暂保存状态。
3. 模拟保存失败。
4. 控件回到原值并出现可关闭的错误提示。

交互动效：
- 页面切换 160ms 淡入。
- Hover/选中 150–200ms 颜色过渡。
- 规则编辑器出现 180–220ms。
- 通知进入 190–240ms，退出最长 520ms。
- Reduced Motion 模式取消位移和缩放，只保留即时状态变化。
```

## 18. 定向修正提示词

### 界面过于稀疏

```text
不要改变信息架构。将当前页面调整为安静的数据密集桌面工具：减少无意义留白，缩小过高卡片，使用 12–16px 内边距和 48–52px 列表行；保留清晰分组，但不要堆叠更多卡片。
```

### 绿色使用过多

```text
当前界面绿色占比过高。将页面主体恢复为白色和中性浅灰，绿色只用于主按钮、开关开启、当前导航、选中行指示线和运行状态。普通面板、标签和大面积背景不得使用绿色。
```

### 圆角和阴影过重

```text
把当前视觉从移动端卡片风格调整为 Windows 生产力工具：面板圆角统一为 8px，控件圆角 6px；移除大部分阴影，以 1px 中性边框建立层级。只保留通知和对话框必要的轻阴影。
```

### 页面像聊天软件

```text
移除聊天气泡、消息输入框、发送按钮、联系人侧栏和社交应用构图。PingNest 只展示通知管理、历史列表、规则和设置，是状态管理工具，不是聊天客户端。
```

### 控件像静态图片

```text
为当前页面所有交互控件补充 Default、Hover、Pressed、Focus、Disabled 和必要的 Selected/Error Variants。确保主按钮、列表行、图标按钮、开关、选择器和滑杆在视觉上明确可操作，但 Hover 不允许缩放或移动布局。
```

### 移动端出现溢出

```text
只修复 390 × 844 响应式布局：禁止横向滚动；将双列区域改为单列；工具栏换行；搜索框独占一行；Select 等宽；通知预览宽度限制在内容区；底部导航固定并为内容预留 62px 空间。
```

### 页面出现虚构功能

```text
删除当前设计中项目未支持的功能，包括聊天回复、账号登录、云同步、复杂报表、导出、在线更新、多显示器管理和直接跳转微信会话。严格恢复为项目事实清单中的现有功能。
```
